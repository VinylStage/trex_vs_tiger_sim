# 방송 설정 가이드

티렉스 대 호랑이 시뮬레이터를 켜 두고 직접 조작하며 생방송하려는 스트리머를 위한 설정 안내다. 첫 시험 방송은 치지직에서 하고, 같은 구성을 YouTube Live와 Twitch에서 이어서 시험한다.

기능 설명은 v0.2.15(`main`의 `d0cc260`) 코드와 실행 화면으로 확인했다. 시간과 화면 비교는 2026-10-26에 이 저장소의 개발 컨테이너에서 잰 값이므로, 방송용 PC에서는 숫자가 달라진다. 외부 링크도 같은 날 열어 확인했다.

- 한국어 화면: <https://trex-vs-tiger.vinylims.com/>
- 영어 화면: <https://trex-vs-tiger.vinylims.com/en/>

시뮬레이션은 화면을 연 브라우저 안에서만 돌고, 설정과 결과는 서버에 저장되지 않는다. 방송에 나오는 숫자는 모두 스트리머 PC가 계산한 값이다.

## 1. 방송에서 쓸 수 있는 기능

### 1.1 클래식과 자유 대결

왼쪽 '시나리오' 패널 맨 위의 '대결 방식'에서 두 모델 중 하나를 고른다. '클래식 (대형 vs 무리)'는 대형 동물 한 종과 무리 동물 한 종이 맞붙는 기존 모델이다. '자유 대결'은 양쪽 진영에 어떤 종이든 놓을 수 있고, 티라노사우루스 대 티라노사우루스 같은 같은 종 대결도 된다. 자유 대결 결과 위에는 '자유 대결 모델은 아직 보정 중입니다. 아래 숫자는 잠정값이니 참고로만 보세요.'가 항상 붙으니, 방송에서도 잠정 모델이라고 한 번 말해 둔다.

| 항목              | 클래식                                                                                                                                                  | 자유 대결                                                                                  |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 고를 수 있는 종   | 대형 6종(티라노사우루스, 아프리카코끼리, 아프리카물소, 불곰, 털매머드, 호모 에렉투스)과 무리 5종(호랑이, 사자, 회색늑대, 점박이하이에나, 호모 에렉투스) | 10종 전부, 양쪽 같은 종 가능                                                               |
| 마릿수            | 대형 1–500, 무리 1–5,000                                                                                                                                | 진영당 1–5,000, 두 진영 합계 최대 5,500                                                    |
| 대결 프리셋       | 9개                                                                                                                                                     | 없음(기본값 T-Rex 1 vs T-Rex 1)                                                            |
| 바꿀 수 있는 가정 | 무리 전술, 사기 · 도주, 22개 능력치 범위('고급: 모델 파라미터 범위')                                                                                    | 사기 · 도주, 무리 버프 효과 5가지 켜고 끄기(사자, 회색늑대, 점박이하이에나, 호모 에렉투스) |
| 결과 화면         | 판정 문장, 요약 카드, 차트 4종                                                                                                                          | 판정 문장, 잠정 모델 안내, 진영별 요약 카드                                                |

호모 에렉투스가 들어간 대결에는 옷 · 도구 · 무기 없이 신체 능력만 비교하는 사고 실험이라는 안내가 함께 나온다. 영어 시청자가 많은 Twitch 방송이라면 헤더의 'English'로 화면 언어를 바꿀 수 있고, 이때 설정과 결과, 재생은 그대로 남는다.

### 1.2 대결 프리셋

클래식에는 프리셋 버튼 9개가 있다. 누르면 양쪽 종, 마릿수, 실행 횟수가 한 번에 바뀌고 능력치 범위가 그 종의 기본값으로 돌아간다. 시드와 경기장 크기 같은 나머지 설정은 그대로 남는다. 범위를 고쳐 둔 상태에서 프리셋을 누르면 알림의 '되돌리기'로 이전 설정을 되살릴 수 있다.

### 1.3 실행 설정과 걸리는 시간

| 설정               | 범위                 | 기본값    |
| ------------------ | -------------------- | --------- |
| 시뮬레이션 횟수    | 1–20,000             | 500       |
| 시드               | 0–4,294,967,295      | 20261019  |
| 경기장 한 변 (m)   | 100–5,000            | 600       |
| 제한 시간 (초)     | 30–3,600             | 1,200     |
| 샘플링 방법        | LHS, 단순 무작위     | LHS       |
| 개체 변동 (CV)     | 0–0.3                | 0.08      |
| 무리 전술 (클래식) | 측면 포위, 정면 돌격 | 측면 포위 |
| 사기 · 도주        | 켬, 끔               | 켬        |

'시뮬레이션 실행'을 누르면 워커 여러 개가 실행을 나눠 계산한다. 워커 수는 CPU 논리 코어 수에서 1을 뺀 값이고 최대 8개다(`src/ui/chunks.ts`). 진행 막대에는 '완료 수 / 전체 횟수 (비율)'이 나오고, 클래식은 남은 시간과 끝난 뒤의 '완료 · 걸린 시간'도 보여 준다. 판정 아래 회색 기준 줄 끝의 '계산 N초'가 실제로 걸린 시간이다.

실행 횟수 × (제한 시간 ÷ 0.1초) × 전체 마릿수가 5×10¹⁰을 넘으면 앱이 실행 횟수를 알아서 줄인다. 클래식은 예상 시간이 1분 이상이면 '무거운 시나리오입니다', 10분 이상이면 '매우 무거운 시나리오입니다'를 마릿수 아래와 실행 버튼 옆에 띄운다. 자유 대결도 같은 한도로 횟수를 줄이지만 경고 문구는 없다. 측정한 계산 시간은 [5.1절](#51-실행-횟수와-계산-시간)에 있다.

### 1.4 결과 화면

- 클래식: 판정 문장, 정밀도 문장(95% 구간), 교육용 모델 안내, 요약 카드(결과별 비율, 전투 시간 중앙값, 평균 생존 · 전투 불능 · 도주, 교환비), 차트 4종(결과별 비율과 95% 구간, 전투 시간 분포, 생존 수 분포, '무엇이 승패를 좌우했나 (상위 10개)')
- 자유 대결: 잠정 모델 안내, 판정 문장, 정밀도 문장, 요약 카드(A · B 진영 승리, 무승부, 전투 시간, 진영별 끝까지 남음 · 이탈 · 전투 불능과 그 비율), 사회성 종 진영의 무리 버프 활성 카드. 진 쪽 무리의 80% 이상이 이탈했으면 판정 아래에 '무리의 사기가 한꺼번에 무너졌어요' 알림이 붙는다.

판정 문장은 '이 모델로 500번 싸워 보니 T-Rex 쪽이 500번 이겼습니다 (> 99%).' 형식이라 그대로 읽어 주기 좋다. 정밀도 문장은 실행 횟수에서 오는 오차만 알려 주고 모델의 가정이 맞는지는 알려 주지 않는다는 점까지 화면에 적혀 있다. 결과가 나온 뒤 설정을 바꾸면 '설정이 바뀌었습니다. 아래 결과는 이전 설정 기준입니다.'가 결과 위에 붙는다.

### 1.5 전투 재생

실행이 끝나면 결과 아래 '전투 재생'이 대표 전투를 다시 계산해 바로 재생한다. 대표 전투는 클래식에서 대형 동물 우세도가 중앙값에 가장 가까운 전투, 자유 대결에서 가장 흔한 결과 가운데 교전 시간이 중앙값에 가장 가까운 전투다. '무작위 전투'는 이번 결과의 실행 가운데 하나를 무작위로 골라 다시 계산하므로 누를 때마다 다른 판이 나온다. 재생 위의 정보 줄에는 '실행 #번호 · 결과 · 교전 시간'이 함께 표시된다.

재생 화면은 동물 모양을 그리지 않고 추상 기호만 쓴다. 클래식은 삼각형이 대형 동물이고, 무리 동물은 상태에 따라 점(접근), 마름모(매달림), 고리(회복), 화살표(도주), ×(전투 불능)로 바뀐다. 자유 대결은 A 진영이 파랑, B 진영이 주황이고, 몸 반경 1 m 이상인 종은 삼각형, 나머지는 점이며, 무리 버프가 켜진 개체에는 얇은 고리가 붙는다. 속도는 0.25×–16×(기본 2×)이고, '보기'는 '자동 (전투 따라가기)'와 '경기장 전체'를 공통으로 고를 수 있다. 클래식에는 대형 동물 중심 2배 · 4배 보기와 '첫 접촉으로', '◀ 이전 사건', '다음 사건 ▶' 버튼이 더 있다.

| 키                             | 클래식                        | 자유 대결                    |
| ------------------------------ | ----------------------------- | ---------------------------- |
| `Space`, `K`                   | 재생 / 일시정지               | 재생 / 일시정지              |
| `←` / `→`                      | 1초 뒤로 / 앞으로             | 1초 뒤로 / 앞으로            |
| `Shift` + `←` / `→`, `J` / `L` | 5초 뒤로 / 앞으로             | 5초 뒤로 / 앞으로            |
| `Page Up` / `Page Down`        | 전체 길이의 10% 앞으로 / 뒤로 | 없음                         |
| `Home` / `End`                 | 처음 / 끝                     | 처음 / 끝                    |
| `[` / `]`                      | 느리게 / 빠르게               | 느리게 / 빠르게              |
| `,` / `.`                      | 이전 / 다음 사건 1초 전       | 없음                         |
| `C`                            | 첫 접촉 2초 전                | 없음                         |
| `F`                            | 자동 보기와 경기장 전체 전환  | 자동 보기와 경기장 전체 전환 |

단축키는 포커스가 재생 영역 안에 있을 때만 동작한다. 재생 화면을 한 번 클릭하면 재생이 토글되고 포커스가 재생 버튼으로 옮겨 가므로, 그다음부터 바로 키를 쓸 수 있다. 두 재생 모두 한글 입력 상태에서도 물리 키 위치로 단축키를 알아듣는다(클래식 `K`, `J`, `L`, `C`, `F`, 자유 대결 `K`, `J`, `L`, `F`). 한/영 키로 영문 입력 상태를 만들어 둘 필요가 없다.

페이지가 숨김 상태가 되면 두 재생 모두 일시정지하고, 다시 보이게 되면 숨기 직전에 재생 중이었던 경우에만 이어서 재생한다. 직접 일시정지해 둔 재생은 그대로 멈춰 있다. 그래서 OBS에서 소스를 숨기거나 브라우저 창을 최소화했다가 되돌려도 '재생'을 다시 누를 필요가 없다.

### 1.6 공유

| 방법                  | 화면 위치                                                     | 담기는 내용                                             | 쓰임                                      |
| --------------------- | ------------------------------------------------------------- | ------------------------------------------------------- | ----------------------------------------- |
| 설정 링크 (`#s=…`)    | 헤더 '설정 링크 복사'                                         | 지금 대결 방식의 설정 전체와 시드                       | 시청자에게 같은 대결 전달                 |
| 설정 코드 `TVT2-…`    | 클래식 '설정 내보내기 · 가져오기'의 '코드 복사', '.json 저장' | 클래식 설정과 시드                                      | 받은 쪽의 미리보기 확인 후 '이 설정 적용' |
| 설정 코드 `TVT3-…`    | 자유 대결 '설정 코드 복사'                                    | 자유 대결 설정과 시드                                   | 받은 쪽의 '확인' 한 번으로 자유 대결 적용 |
| 결과 링크 (`/r/?r=…`) | 결과 아래 '결과 공유', '결과 페이지 열기'                     | 설정과 이번 결과의 스냅샷                               | 결과 공개와 시청자 재현                   |
| 결과 카드 이미지      | 결과 페이지의 '이미지 형식', '이미지 저장'                    | 스토리 9:16(1080×1920) 또는 정사각형 1:1(1080×1080) PNG | 방송 마지막 화면, 커뮤니티 게시물         |
| 텍스트 공유           | 결과 페이지의 '텍스트 공유'                                   | 이모지 막대, 비율, 결과 링크                            | 채팅용 한 줄 요약                         |

설정 코드는 클래식 화면의 '코드 또는 링크 붙여넣기' 칸에 넣고 '확인'을 누르면 읽힌다. `TVT2-` 코드는 대결, 실행 횟수, 시드를 보여 주는 미리보기를 거쳐 '이 설정 적용'을 눌러야 바뀌고, `TVT3-` 코드는 미리보기 없이 자유 대결로 바로 바뀐다. 어느 쪽도 실행을 저절로 시작하지는 않는다.

'결과 공유'는 브라우저가 공유 기능(Web Share)을 지원하면 운영체제 공유 창을 먼저 열고, 지원하지 않으면 링크를 복사한다. 결과 링크를 채팅에 붙이려면 '결과 페이지 열기'로 연 새 탭의 주소를 복사하거나 결과 페이지의 '링크 복사'를 쓰는 편이 단순하다. 복사 버튼은 클립보드를 쓸 수 없는 환경에서 텍스트를 선택해 둔 대화상자를 띄운다.

시청자가 결과 페이지에서 '이 설정으로 직접 실행'을 누르면 같은 설정의 시뮬레이터가 열린다. 설정을 바꾸지 않고 실행하면 '공유된 결과와 정확히 같은 결과가 나왔습니다', '재현됨: 공유된 승률이 이번 실행의 95% 신뢰구간 안에 있습니다', '차이 있음' 가운데 하나가 뜬다. Chrome, Edge, 웨일처럼 V8 엔진을 쓰는 브라우저는 숫자가 정확히 같고, 아이폰 브라우저처럼 JavaScriptCore를 쓰는 환경은 통계적으로 같은 숫자를 낸다([SHARING.md](SHARING.md#result-links)).

## 2. OBS 설정

### 2.1 방식 고르기

OBS에 이 사이트를 넣는 방법은 브라우저 소스와 창 캡처 두 가지다. 클릭과 입력이 많은 방송이라면 일반 Chrome이나 Edge 창을 띄우고 창 캡처로 잡는 방식을 권한다. 브라우저 소스는 OBS에 들어 있는 내장 브라우저(CEF)라서 아래 표처럼 일부 동작이 막힌다. 표의 브라우저 소스 제한은 obs-browser 소스 코드(`browser-client.cpp`, `obs-browser-source.cpp`)에서 확인했다.

| 항목                          | 브라우저 소스                                               | 창 캡처 (Chrome · Edge)                   |
| ----------------------------- | ----------------------------------------------------------- | ----------------------------------------- |
| 클릭 · 키보드 입력            | 소스 우클릭 → '상호작용' 창에서만 가능                      | 평소 브라우저 조작 그대로                 |
| 드롭다운(종, 속도, 보기 선택) | 펼친 목록이 그려지지 않음, `Tab`으로 포커스 후 `↑`/`↓` 변경 | 정상                                      |
| '결과 페이지 열기'(새 탭)     | 열리지 않음(팝업 차단)                                      | 새 탭으로 열림                            |
| '.json 저장', '이미지 저장'   | 저장되지 않음(다운로드 처리기 없음)                         | 정상                                      |
| 사용자 지정 CSS               | 적용되지 않음(사이트 CSP)                                   | 해당 없음                                 |

| 장점                          | OBS 장면 안에서 관리, 창 배치 불필요                        | 배율을 올려도 선명한 글자, 모든 기능 사용 |

### 2.2 브라우저 소스

| 속성 (OBS 한국어 표기)                    | 권장값                                                                 | 이유                                                         |
| ----------------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------ |
| URL                                       | `https://trex-vs-tiger.vinylims.com/` 또는 미리 만든 설정 링크(`#s=…`) | 설정 링크를 넣으면 그 대결이 채워진 상태로 열림              |
| 너비 · 높이                               | 1080p 캔버스는 1536 × 864 후 '화면에 맞추기', 720p 캔버스는 1280 × 720 | [3절](#3-화면-가독성-점검) 권장 배율(125%, 100%)과 같은 화면 |
| 사용자가 임의로 설정한 프레임 레이트 사용 | 끔                                                                     | OBS 캔버스 FPS에 맞춰 그림                                   |
| 사용자 지정 CSS                           | 비워 둠                                                                | 사이트 CSP 때문에 적용되지 않음                              |
| 소스가 보이지 않는 경우 종료              | 끔                                                                     | 숨길 때마다 결과와 재생이 사라지는 문제 방지                 |
| 장면이 활성화되면 브라우저를 새로고침     | 끔                                                                     | 장면 전환마다 처음 상태로 돌아가는 문제 방지                 |
| 페이지 권한                               | OBS에 접근 권한 없음                                                   | 사이트가 OBS 기능을 쓰지 않음                                |

'소스가 보이지 않는 경우 종료'를 켜면 소스를 숨기거나 다른 장면으로 갈 때 OBS가 페이지를 닫고, 다시 보일 때 속성에 적힌 URL로 새로 연다. 메모리는 아끼지만 결과, 재생, 상호작용 창에서 바꾼 설정이 모두 사라진다. '장면이 활성화되면 브라우저를 새로고침'을 켜면 장면에 돌아올 때마다 같은 일이 생긴다. 둘 다 끈 상태에서 소스가 안 보이면 OBS가 페이지에 숨김 상태를 알리고, 재생 루프가 멈추며 계산을 마친 워커는 대기한다. 장면으로 돌아오면 숨기 전에 재생 중이었던 전투가 저절로 이어서 재생된다.

프레임 레이트 항목을 끄면 브라우저 소스가 OBS 캔버스 FPS로 그린다. PC 부하를 줄이려면 켜고 30으로 둔다. 클래식 재생의 화질 조절은 30fps로 고르게 고정된 화면을 느린 화면으로 보지 않으므로([REPLAY.md §10](REPLAY.md#10-adaptive-quality)), 30fps에서도 효과와 자취를 줄이지 않는다. OBS '설정 → 고급'의 '브라우저 소스에 하드웨어 가속 활성화'는 기본값(켬)으로 둔다. 이 값은 OBS가 시작할 때 읽으므로 바꾼 뒤에는 OBS를 다시 시작해야 한다.

조작은 소스를 우클릭하고 '상호작용'을 골라 여는 별도 창에서 한다. 이 창에서 클릭, 휠 스크롤, 키 입력이 페이지로 전달된다. obs-browser는 드롭다운의 펼친 목록 같은 팝업 화면을 그리지 않으므로, 종이나 속도를 바꿀 때는 `Tab`으로 드롭다운에 포커스를 옮긴 뒤 `↑`/`↓`로 값을 고른다. 자유 대결은 종 선택이 모두 드롭다운이라 이 과정이 번거롭다. 대결을 미리 정할 수 있다면 설정 링크를 URL 칸에 넣어 두는 편이 빠르다.

브라우저 소스는 일반 Chrome과 저장소가 따로라서 처음 열면 '처음 오셨나요?' 안내가 뜬다. 상호작용 창에서 '괜찮아요'를 한 번 누르면 그 저장소에 기록되어 다시 나오지 않는다. 방송 도중 사이트가 새로 배포되면 화면 아래에 '새 버전이 배포되었습니다' 배너가 뜨는데, '나중에'를 누르면 그 배포에 대해서는 사라진다. 버전 확인은 30분마다, 그리고 페이지가 다시 보일 때 한 번씩 일어난다.

배율은 사용자 지정 CSS로 바꿀 수 없다. OBS는 사용자 지정 CSS를 `<style>` 요소로 페이지에 넣는데, 이 사이트의 CSP(`style-src 'self'`)가 인라인 스타일을 막는다. 실제 사이트에서 OBS와 같은 스크립트로 `html { zoom: 1.25; }`와 OBS 기본 CSS를 넣어 보니 둘 다 'Refused to apply inline style' 오류와 함께 무시됐다. 기본 CSS의 `overflow: hidden`도 적용되지 않으므로 칸을 그대로 두어도 해는 없지만, 효과가 없으니 비워 둔다. 브라우저 소스 속성에는 배율 항목도 없다(OBS의 배율 메뉴는 브라우저 독에만 있다).

그래서 브라우저 소스에서는 너비와 높이를 '캔버스 ÷ 배율'로 잡고 OBS에서 키운다. 1920×1080 캔버스에 125%를 원하면 1536 × 864로 만들고, 소스 우클릭 → '변환' → '화면에 맞추기'를 고른다. 1536픽셀로 그린 화면을 1.25배로 늘리는 방식이라 글자 가장자리는 창 캡처보다 조금 흐리다.

### 2.3 창 캡처 (클릭이 많은 방송에 권장)

1. 방송 전용 브라우저 창: `chrome.exe --app=https://trex-vs-tiger.vinylims.com/`처럼 `--app`으로 연 탭 · 주소창 없는 창(Edge는 `msedge.exe --app=…`)
2. 배율: `Ctrl` + `+` 두 번으로 125%(100 → 110 → 125%), `Ctrl` + `0`으로 100%
3. 창 크기: 페이지 영역 16:9, 페이지 영역 너비 ÷ 배율이 1,000 이상
4. OBS 소스: '윈도우 캡쳐', '윈도우'에서 브라우저 창 선택, '캡쳐 방식'은 '자동', '커서 캡쳐'는 켬
5. 배치: 소스 우클릭 → '변환' → '화면에 맞추기', 탭이나 주소창이 보이면 `Alt`를 누른 채 소스 가장자리를 끌어 자르기

Chrome과 Edge는 사이트마다 배율을 기억하므로 한 번 맞추면 다음 방송에도 유지된다. 페이지 영역 너비를 배율로 나눈 값이 1,000보다 작아지면 화면이 1단으로 바뀌므로([3절](#3-화면-가독성-점검)), 창을 줄일 때는 배율도 함께 낮춘다. 커서를 켜 두면 시청자가 어느 버튼을 누르는지 따라올 수 있다.

OBS의 '자동' 캡쳐 방식은 창 클래스 이름에 Chrome이 들어간 창, 곧 Chrome과 Edge 창에 '신식 (WGC)'을 고른다(OBS `plugins/win-capture/window-capture.c`). WGC는 GPU로 그린 브라우저 창도 잡으므로 브라우저의 하드웨어 가속을 켠 채로 쓰면 된다. 화면이 검게 나오면 '캡쳐 방식'을 '신식 (WGC)'으로 직접 고른다. WGC를 지원하지 않는 Windows라서 '구식 (BitBlt)'만 쓸 수 있다면 브라우저의 그래픽 가속을 끈다. Chrome은 '설정 → 시스템 → 가능한 경우 그래픽 가속 사용'(`chrome://settings/system`), Edge는 `edge://settings/system`에 있고, 바꾼 뒤에는 브라우저를 다시 시작한다. 가속을 끄면 재생 화면을 CPU가 그린다. 소프트웨어 렌더링 헤드리스 Chromium에서 재생은 10v100에서 60fps, 500v5000에서 58fps 이상이 나온 기록이 있다([REPLAY.md §12](REPLAY.md#12-tests-and-measurements), 실제 기기 측정값은 아님).

창을 최소화하면 페이지가 숨김 상태가 되어 재생이 멈추고, 창을 되돌리면 이어서 재생한다. 창 캡처는 다른 창에 가려진 창도 잡지만([OBS 문서](https://obsproject.com/kb/window-capture-sources)), Windows의 Chrome은 완전히 가려진 창을 숨김 상태로 다루기도 하므로 재생이 멈추면 창을 앞으로 꺼낸다. 모니터가 둘이면 브라우저 창을 보조 모니터에 두는 편이 조작하기 편하다.

치지직 고객센터의 방송 시작 방법은 송출 프로그램으로 프리즘과 OBS를 함께 든다. 프리즘을 쓴다면 [PRISM Live Studio](https://prismlive.com/ko_kr/)에서 받고, 이 문서의 항목 이름은 OBS 기준이라는 점을 감안한다.

## 3. 화면 가독성 점검

`npm run build`로 만든 v0.2.15 코드(`d0cc260`)를 `vite preview`로 띄우고, Playwright의 헤드리스 Chromium으로 1920×1080과 1280×720 화면을 찍었다. 브라우저 배율은 CSS 뷰포트를 줄이고 기기 픽셀 비율을 올려 흉내 냈다. 예를 들어 1280×720의 125%는 1024×576 뷰포트에 픽셀 비율 1.25다. 찍은 화면은 첫 화면, 자유 대결 결과(호랑이 5 vs 사자 5, 500회), 클래식 기본 대결과 자유 대결의 재생이고, 스크린샷은 저장소에 넣지 않았다.

| 1280×720 · 110%  | 1164×655   | 2단       | 16.5                 | 566                        | 판정 문장 두 줄, 요약 카드 3열                                                               |
| 1280×720 · 125%  | 1024×576   | 2단       | 18.75                | 545                        | 판정 문장 두 줄, 요약 카드 3열, 재생 화면 436 CSS px                                         |
| 1280×720 · 150%  | 853×480    | 1단       | 22.5                 | 510                        | 설정 아래에 결과가 쌓이고 하단 고정 실행 바가 화면 일부를 가림, 페이지 높이 9–11화면         |

시청자 화면에서 글자가 얼마나 크게 보이는지는 캔버스 해상도보다 CSS 뷰포트 높이가 정한다. 1080p 캔버스의 150%와 720p 캔버스의 100%는 둘 다 1280×720 뷰포트라서 영상 안에서 같은 크기로 보인다. 화면을 비교해 정한 권장값은 다음과 같다.

- 1080p 캔버스: 125%(뷰포트 1536×864)
- 720p 캔버스: 100%(뷰포트 1280×720)
- 금지: 뷰포트 너비가 1,000 px보다 작아지는 배율(1단 전환)

1080p에서 125%를 고른 이유는 2단 구성을 유지하면서 글자가 1.25배 커지고, 재생 화면과 그 아래 조작 줄이 한 화면에 들어오기 때문이다. 재생 화면 한 변은 최대 620 CSS px이고 '뷰포트 높이 − 140 px'를 넘지 않으므로, 뷰포트가 낮아질수록 재생 화면이 먼저 줄어든다. 휴대폰 시청자가 많아 글자를 더 키우고 싶다면 150%까지 올릴 수 있다. 이때 재생을 보여 주면 버튼 줄이 화면 밖으로 밀리므로 단축키로 조작한다. 720p 캔버스에서 125%를 쓰면 글자는 커지지만 재생 화면이 436 CSS px로 줄고 판정 문장이 두 줄로 접힌다.

2단 구성에서는 왼쪽 설정 패널이 따로 스크롤되고 '시뮬레이션 실행' 버튼이 패널 아래쪽에 고정된다. 결과와 재생을 보여 주는 동안에도 설정을 고쳐 다시 실행할 수 있다. 재생 화면이 작을수록 무리 동물을 작은 사각형으로 그리는 원거리 표시가 빨리 켜지고, 그때 '멀리서는'으로 시작하는 안내가 재생 화면 아래쪽에 겹친다. '보기'를 '자동 (전투 따라가기)'로 두면 교전이 시작될 때 화면이 확대되면서 안내가 사라지기도 한다.

## 4. 30분 시청자 참여 방송 구성

지금 기능만으로 30분을 채우는 구성 예시다. 앱은 채팅을 읽지 못하므로 투표는 플랫폼 기능이나 채팅 집계로 받는다. 치지직은 스트리머가 주제를 정하고 시청자가 통나무 파워로 참여하는 승부예측, YouTube는 실시간 채팅의 설문조사, Twitch는 채널 포인트 예측을 쓸 수 있다([2.4절](#24-공식-문서)).

| 시간    | 코너                    | 화면 조작                                                                       | 시청자 참여                                                  |
| ------- | ----------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 0–3분   | 소개                    | 첫 화면, 결과 아래 교육용 모델 안내와 '모델의 가정 보기'                        | 없음                                                         |
| 3–10분  | 프리셋 예측             | 프리셋 '물소 1마리 vs 사자 6마리'(1,000회) 실행, 정밀도 문장과 민감도 차트 읽기 | 실행 전 예측 또는 설문: 물소 승리 / 사자 승리 / 무승부       |
| 10–18분 | 시청자가 짜는 자유 대결 | '자유 대결'에서 A · B 진영 종과 수 입력, 같은 종 대결 한 번                     | 채팅의 종 · 수 제안, 득표 1위 채택                           |
| 18–23분 | 재생 반전               | '대표 전투' 뒤 '무작위 전투', 클래식이면 `C` · `,` · `.`, 속도 `[` · `]`        | 무작위 전투의 승자 맞히기                                    |
| 23–27분 | 가정 바꾸기             | 사회성 종 진영의 무리 버프 효과 하나를 끄고 재실행, 이전 결과와 비교            | 끌 효과 투표                                                 |
| 27–30분 | 결과 공유               | '결과 페이지 열기', 결과 페이지의 결과 카드와 링크                              | 결과 링크의 '이 설정으로 직접 실행'으로 재현, 재현 문구 채팅 |

코너별로 덧붙일 내용은 아래와 같다.

- 예측 선택지: 승패 세 갈래, 또는 승률 구간(50% 미만, 50–70%, 70% 이상)
- 채팅 형식: 'A 늑대 20 / B 불곰 2'처럼 진영, 종, 수를 한 줄에 쓰는 고정 형식
- 같은 종 대결: 자유 대결 T-Rex 1 vs T-Rex 1, 500회의 측정값 B 진영 51%(254회), 50% 근처 숫자와 95% 구간 설명 소재
- 박빙 대결 후보: 물소 1 vs 사자 6(사자 58.9%), 불곰 1 vs 늑대 8(불곰 57.6%), 자유 대결 호랑이 5 vs 사자 5(사자 60%)
- 무작위 전투 맞히기: 정보 줄에 승자와 교전 시간이 바로 표시되므로, 재생 화면만 보이도록 스크롤하거나 OBS에서 정보 줄을 가린 상태로 진행
- 시드 뽑기(클래식): 같은 대결을 100회로 두고 시청자가 낸 시드로 차례로 실행, 시드마다 승률이 조금씩 다른 이유(표본 오차) 설명
- 결과 검증: Chrome 계열 시청자는 '정확히 같은 결과', 아이폰 시청자는 대개 '재현됨'
- 마무리: 자유 대결 '설정 코드 복사'로 만든 `TVT3-` 코드를 채팅에 올려 다음 방송 대결 후보 받기

방송 흐름을 끊지 않으려면 생방송 중 실행은 500–2,000회로 둔다. 이 컨테이너에서 그 범위의 실행은 1–12초 걸렸다([5.1절](#51-실행-횟수와-계산-시간)). 진행 중에는 '실제 싸움의 예측이 아닙니다'라는 화면 안내를 살린다. 용어는 화면과 같은 전투 불능, 도주, 교전을 쓰고, 학살이나 피 같은 표현은 쓰지 않는다([CONTRIBUTING.md](../CONTRIBUTING.md#content-framing-rules)).

### 아직 없는 기능

지금 버전에는 방송 전용 기능이 없다. 아래 항목은 구현되어 있지 않고, 이 문서는 구현 일정을 다루지 않는다.

- 채팅 연동(시청자 투표나 채팅 명령을 앱이 직접 읽는 기능)
- 스트리머 모드(설정 패널을 숨긴 방송용 화면)
- 토너먼트 모드(대진표와 연속 대결 기록)
- 실시간 변수 카드(방송 중 변수를 카드로 띄우고 바꾸는 기능)

## 5. 성능

### 5.1 실행 횟수와 계산 시간

측정 환경은 이 저장소의 개발 컨테이너(Intel Xeon 2.80 GHz 4 vCPU, 메모리 15 GB), Playwright 헤드리스 Chromium, `vite preview`로 띄운 v0.2.15 코드(`d0cc260`) 빌드다. 워커는 3개(코어 4개 − 1)였고 OBS 같은 인코더는 돌지 않았다. 시간은 결과 기준 줄의 '계산 N초' 값이며, 같은 스크립트를 세 번 돌려 중앙값과 범위를 적었다.

| 설정                            | 실행 횟수 | 계산 시간 중앙값 | 범위        |
| ------------------------------- | --------- | ---------------- | ----------- |
| 클래식 T-Rex 10 vs 호랑이 100   | 100       | 1.8초            | 1.7–2.9초   |
| 클래식 T-Rex 10 vs 호랑이 100   | 500       | 4.1초            | 3.9–5.4초   |
| 클래식 T-Rex 10 vs 호랑이 100   | 2,000     | 11.5초           | 10.9–14.8초 |
| 클래식 T-Rex 1 vs 호랑이 10     | 1,000     | 5.5초            | 5.3–7.3초   |
| 클래식 T-Rex 50 vs 호랑이 1,000 | 100       | 11.1초           | 11.0–12.8초 |
| 자유 대결 T-Rex 1 vs T-Rex 1    | 500       | 1.2초            | 1.1–1.6초   |
| 자유 대결 호랑이 5 vs 사자 5    | 500       | 2.2초            | 1.9–2.3초   |
| 자유 대결 호랑이 5 vs 사자 5    | 2,000     | 4.4초            | 4.3–5.2초   |
| 자유 대결 늑대 8 vs 불곰 1      | 1,000     | 4.4초            | 4.2–4.7초   |
| 자유 대결 사자 30 vs 코끼리 5   | 500       | 5.2초            | 5.2–5.8초   |

실행 횟수가 늘수록 시간이 길어지지만, 워커 시작과 집계에 드는 고정 시간이 있어 정확히 비례하지는 않는다. 마릿수는 한 판의 길이를 크게 늘린다. T-Rex 50 vs 호랑이 1,000은 100회만으로 기본 대결 2,000회와 비슷한 시간이 걸렸다.

방송 PC는 워커 수가 '코어 수 − 1'(최대 8)이라 코어가 많으면 더 빨라질 수 있다. 반대로 방송 중에는 OBS 인코딩이 같은 CPU를 나눠 쓴다. 치지직은 GPU에 맞는 하드웨어 인코더를 권하며 x264는 피하라고 안내하고, Twitch 안내도 x264가 CPU를 많이 쓴다고 적는다. 하드웨어 인코더를 쓰면 시뮬레이션에 CPU를 더 남길 수 있다. 방송 전에 OBS를 켠 상태로 기본 대결 500회를 한 번 돌려 '계산 N초'를 적어 두면, 이 표와 비교할 그 PC의 기준값이 생긴다.

### 5.2 동작 줄이기

운영체제에서 애니메이션을 끄면 브라우저가 동작 줄이기(`prefers-reduced-motion: reduce`)를 켠 것으로 알린다. Windows 11에서는 '설정 → 접근성 → 시각 효과 → 애니메이션 효과'가 이 값을 정한다([MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion)). 이 설정이 켜져 있으면 재생이 자동으로 시작하지 않는다.

- 클래식: 전투 전체를 한 장으로 요약한 그림(이동 경로, 매달린 곳, 쓰러진 곳), '재생'을 누르면 효과와 자취 없이 재생
- 자유 대결: '동작 줄이기 설정이 켜져 있어 자동으로 재생하지 않습니다' 안내, '재생'을 누르면 시작

Playwright에서 동작 줄이기를 켜고 실행해 보니 결과가 나오고 3초 뒤에도 재생 위치가 0.0초에 머물렀고, 위 안내가 그대로 표시됐다. 방송에서 재생이 저절로 시작하지 않으면 이 설정부터 확인한다. 클래식의 요약 그림은 한 판 전체를 한 화면에 보여 주므로 설명용으로 일부러 쓸 수도 있다.

### 5.3 여러 탭

시뮬레이터 페이지는 탭마다 워커 풀을 따로 만든다. 기본 대결 500회를 한 탭에서 돌리면 5.3–6.0초, 두 탭에서 동시에 돌리면 탭마다 9.9–10.6초가 걸렸다(이 컨테이너, 2회 측정). OBS 브라우저 소스도 페이지 하나로 치므로, 브라우저 소스와 Chrome 창에 시뮬레이터를 함께 띄워 두지 않는다. 앱은 페이지가 숨김 상태가 될 때 재생만 멈추고 진행 중인 계산은 취소하지 않는다.

## 6. 방송 시험 체크리스트

### 방송 전

- [ ] 헤더 버전 배지 확인(`v0.2.x` 옆 '최신')
- [ ] 첫 방문 안내 정리('괜찮아요', 브라우저 소스는 별도로 한 번 더)
- [ ] 배율 확인(1080p 캔버스 125%, 720p 캔버스 100%)
- [ ] 캡처 화면 확인(검은 화면, 잘림, 탭 · 주소창 노출)
- [ ] OBS를 켠 상태의 기본 대결 500회 계산 시간 기록
- [ ] 재생 자동 시작 확인(동작 줄이기 꺼짐)
- [ ] 재생 단축키 확인(재생 화면 클릭 후 `Space`, 한글 입력 상태에서 `K`)
- [ ] 결과 링크 복사와 채팅 붙여넣기 시험
- [ ] 방송에 쓸 설정 링크(`#s=…`) 준비
- [ ] 시뮬레이터 페이지 정리(하나만 남김)
- [ ] 송출 프로그램의 하드웨어 인코더 설정 확인
- [ ] 방송 제목 · 설명의 교육용 시뮬레이션 문구 확인

### 방송 중

- [ ] 자유 대결 결과의 잠정 모델 안내 언급

- [ ] 피드백 이슈 등록

## 7. 피드백 보내기

방송에서 찾은 문제와 요청은 GitHub 이슈로 남긴다: <https://github.com/VinylStage/trex_vs_tiger_sim/issues/new/choose>. 오작동은 'Bug report', 방송용 기능 요청은 'Feature request' 양식을 고른다. 이슈에는 아래 내용을 적는다.

- 설정 링크 또는 결과 링크
- 브라우저와 OS, OBS 버전
- 캡처 방식(브라우저 소스, 창 캡처), 배율, 캔버스 해상도
- 방송 플랫폼과 다시보기 시각
- 기대한 동작과 실제 동작

스트림 키가 보이는 화면은 첨부하지 않는다. 치지직 고객센터도 스트림 키가 공유되면 다른 사람이 그 채널로 방송할 수 있다고 안내한다.
