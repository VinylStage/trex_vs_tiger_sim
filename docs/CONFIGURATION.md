# Configuration Reference

Declarative config files (JSON, YAML, `_headers`, `_routes.json`, `tsconfig.json`, `vite.config.ts`, `eslint.config.js`) intentionally carry **no inline comments**; this page documents them. Build code such as the Vite plugins (`vite.pages.ts`, `vite.seo.ts` and `src/seo`) is code, documented in place with JSDoc like `src/`, and summarised here. The one exception is the `# vX.Y.Z` after each SHA-pinned action in `.github/workflows/*.yml` ([GitHub Actions pinning](#github-actions-pinning)): Dependabot reads and rewrites it, so it is part of the pin, not documentation.

## GitHub Actions pinning

Every third-party action is pinned to a full 40-character commit SHA followed by the release it points to, e.g. `actions/checkout@<sha> # v7.0.1` ([#57](https://github.com/VinylStage/trex_vs_tiger_sim/issues/57)). A moved or hijacked tag cannot change what runs; this matters most for `release-please.yml`, whose job can write to `main`. Dependabot's `github-actions` ecosystem keeps the pins current: its PRs replace the SHA and rewrite the version comment. To pin a new action by hand, resolve the release tag with `git ls-remote --tags https://github.com/<owner>/<repo>` (for an annotated tag, use the `^{}` line, which is the commit). Local reusable workflows (`uses: ./.github/workflows/…`) need no pin.

Repository settings that complete this are owner actions, not files: a branch ruleset on `main` that requires a pull request and the `check` status and blocks force pushes and deletion, and optionally **Settings → Actions → General → "Require actions to be pinned to a full-length commit SHA"**.
