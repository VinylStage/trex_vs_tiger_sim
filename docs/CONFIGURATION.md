# Configuration Reference

Config files in this repository intentionally carry **no inline comments**. Each file is documented here.

| File                                                           | Purpose                                                                                                  | Notes                                                                                                                                                                                                                                                      |
| -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `package.json`                                                 | npm metadata, scripts, dev dependencies                                                                  | `typescript` is pinned to `~6.0.x` because `typescript-eslint@8` declares `typescript >=4.8.4 <6.1.0` as a peer. Revisit when typescript-eslint supports TS 7.                                                                                             |
| `.node-version`                                                | Node major used by CI (`actions/setup-node` `node-version-file`) and the Cloudflare Pages v3 build image | `24` (Active LTS). Pages v3 reads `.node-version`, not `package.json` `engines`. Vite 8 / Vitest 5 / ESLint 10 need `>=22.12`; `engines` keeps that floor for local dev.                                                                                   |
| `tsconfig.json`                                                | Type-check only (`noEmit`); Vite does the transpile                                                      | `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes` are enabled. `lib` is DOM-only; worker globals are typed locally in the worker entry.                                                                                                   |
| `vite.config.ts`                                               | Build + Vitest config                                                                                    | `base: './'` keeps asset URLs relative (works on any Pages subpath/preview). Workers are bundled as ES modules. Tests run in the `node` environment.                                                                                                       |
| `eslint.config.js`                                             | ESLint flat config                                                                                       | `@eslint/js` recommended + `typescript-eslint` strict. Browser + worker globals.                                                                                                                                                                           |
| `.prettierrc.json` / `.prettierignore`                         | Formatting                                                                                               | Single quotes, trailing commas, width 100. `CHANGELOG.md` and `.release-please-manifest.json` are ignored (owned and rewritten by release-please). `src/assets/fonts` (vendored Pretendard, ADR-0005) is ignored.                                          |
| `.editorconfig`                                                | Editor defaults                                                                                          | LF, 2 spaces, UTF-8.                                                                                                                                                                                                                                       |
| `release-please-config.json` / `.release-please-manifest.json` | Release automation                                                                                       | `release-type: node`. `bump-minor-pre-major: true` → while `<1.0.0`, `feat!` bumps minor instead of major. `initial-version: 0.1.0` → the first release is 0.1.0 (release-please otherwise defaults to 1.0.0 when no prior release exists).                |
| `.github/workflows/ci.yml`                                     | CI                                                                                                       | typecheck → lint → format check → unit tests → build. Runs on every PR and on `main`.                                                                                                                                                                      |
| `.github/workflows/release-please.yml`                         | Release PR / tag / GitHub Release                                                                        | Needs repo setting **Settings → Actions → General → Workflow permissions → "Allow GitHub Actions to create and approve pull requests"**.                                                                                                                   |
| `.github/workflows/labels.yml` + `.github/labels.yml`          | Label sync                                                                                               | `skip-delete: true` — never removes labels that are not in the file.                                                                                                                                                                                       |
| `.github/dependabot.yml`                                       | Weekly dependency PRs                                                                                    | npm updates grouped; cooldown 7 days (14 for semver-major) before proposing a fresh release. `typescript >=6.1.0` is ignored because of the typescript-eslint peer range (see `package.json` row); remove the ignore when typescript-eslint supports TS 7. |
| `public/_headers`                                              | Cloudflare Pages response headers                                                                        | See [DEPLOYMENT.md](DEPLOYMENT.md).                                                                                                                                                                                                                        |
