About the T-Rex vs Tiger Simulator

An open-source educational simulator that starts from a fun question, “who would win, a T-Rex or a pack of tigers?”, and uses it to show how to reason under uncertainty.

What this site is

The T-Rex vs Tiger Simulator is a web tool that re-runs a clash between N adult Tyrannosaurus rex and M adult tigers on an open plain hundreds or thousands of times. Rather than showing one fight, it draws traits from published values and explicit assumptions, varies them from run to run, and summarises the outcomes as win probabilities, confidence intervals, distributions and a sensitivity ranking.

You can change the scenario (head counts, tactic, morale) and the range of every one of the 22 traits, and share any setup with a single link. There is nothing to sign up for or install: every calculation happens inside your browser.

What you can learn

The dinosaur-versus-big-cat match-up is the hook. What the site really explores is:

  • Monte Carlo simulation: approximating an answer that has no simple formula by repeating randomised experiments, and watching how the estimate settles as runs increase.
  • Kinds of uncertainty: why “we do not know the value” (epistemic) and “individuals differ” (aleatory) are handled separately.
  • Agent-based modelling: how simple rules for individuals add up to group-level outcomes such as a mass rout or a long war of attrition, visible in the replay.
  • Sensitivity analysis: finding which assumptions drive the result with rank correlations, then testing how robust a conclusion is by changing them.
  • Honest statistics: Wilson confidence intervals, percentiles and histograms, with real numbers to look at.

It works well as a classroom or club prompt for discussing how conclusions depend on assumptions. New here? Start with the tutorial in the guide.

An educational model

T. rex (about 68–66 million years ago) and tigers never lived at the same time, and no such fight has ever happened. Every interaction rule (latching, shaking off, bleeding, morale, group tactics) is an assumption, and some traits have no direct data and are estimated with wide ranges. The win probabilities are what the model produces under those assumptions, not a scientific prediction about real animals.

Which values are literature-based and which are speculative is marked in the parameter reference; the rules and their limits are described in How the model works.

How it is built

  • A static website: no server-side program, just HTML, CSS and JavaScript files served by Cloudflare Pages. There are no accounts and no database, and the site currently uses no analytics.
  • Computation in your browser: battles run in Web Workers spread over your CPU cores. The random numbers are designed so that a given seed gives the same results whatever the number of workers.
  • No external libraries: the simulation engine, charts and replay are written from scratch in TypeScript, so the simulator itself does not depend on any third-party script.
  • A strict security policy: a Content Security Policy only allows this site's own files to run.
  • Tested: the engine, the statistics and the share-link parsing are covered by automated tests, and the parameter values on these help pages are checked against the simulator code automatically.

Open source

The complete source code and documentation are on GitHub at VinylStage/trex_vs_tiger_sim under the MIT License. You are welcome to read the code, run it on your own computer and adapt it.

  • Every rule, constant and reference of the model is collected in MODEL.md.
  • To contribute, see CONTRIBUTING.md. Every change goes through an issue and a pull request.
  • New published values, better sources and reports of model errors are just as valuable. Please cite a source when you propose a parameter change.

Contact

Questions, bug reports and feature ideas are handled through GitHub issues. Issues are public, so please do not include personal information.

  1. Search the GitHub issues to see whether someone has already raised the same point.
  2. If not, open a new issue. You need a GitHub account.
  3. For a bug, include the scenario link from Copy link, your browser and device, and what you expected versus what happened. The same link reproduces the same results, which makes causes much easier to find.

Please report security vulnerabilities privately through the repository's Security tab rather than in a public issue. For how data is handled, see the privacy policy.
